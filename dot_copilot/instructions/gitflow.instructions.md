## Source Control Policy

### Auto-Commit
**Commit when ALL true:**
- Single concern (1 feature/fix/refactor, ≤5 files changed)
- ≤100 lines diff (excludes: tests, autogenerated, env-only configs)
- Tests pass + new code has test coverage
- No open TODOs in changed code
- No changes to: exported APIs, config schemas, protected files (see below)

**Protected files (always require explicit user review):**
- Auth, crypto, secret, password, token, key, vault (case-insensitive in path)
- .github/workflows/, infrastructure/, deployment/
- .env, secrets.yml, credentials.json
- Project overrides: .copilot/project-config.md

**If uncertain:** Ask user before committing.

**Tie-breaker:** Ask user. If no response, apply most restrictive criterion.

---

### Push & Protected Branches
**Policy:** User request only. Never autonomous.

**Protected branches (main, master, production, staging, protected/*, release/*):**
- ALL changes require PR from a new branch (never direct commits)
- PR must be approved before push
- Require explicit "Proceed" confirmation

**Pre-flight:** CI/CD passes, conflicts resolved locally, target confirmed.

---

### Pull Requests
**Policy:** User-initiated only. K1ra generates summary; user must explicitly request submission.

**K1ra generates:** auto-summary, file list, breaking-tags (if [BREAKING] in commits).

**User provides:** base, head, title, body. Reviews and edits before "Proceed" to submit.

---

### Confirmation Gates (K1ra Integration)
- **Local, safe:** one-line summary → proceed
- **Protected branches, PRs, destructive Git ops (force-push, branch delete):** summary/description → require "Proceed"

Note: Local workspace file deletion is handled separately in K1ra's confirmation policy (immediate, with summary). This section addresses Git-level operations only.

---

### Scope
- All Git ops in current repo
- Exceptions: .copilot/project-config.md (project overrides)
- Emergency: user can request "force" + explicit confirmation
